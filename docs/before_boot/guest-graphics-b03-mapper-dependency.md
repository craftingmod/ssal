# SSAL B0.3 — ANGLE Gralloc Mapper Dependency Trace

2026-11-19 KST · **호출 경로 추적 PASS.** `eglInitialize`에서 ANGLE이 `VK_NULL_HANDLE`로 표면 포맷 개수를 조회할 때 Android Vulkan Loader가 RGB565의 `AHardwareBuffer_isSupported`를 호출한다. 이 함수가 빈 `GraphicBuffer`를 생성하면서 `GraphicBufferMapper` 초기화가 시작된다. 기본 실행은 Gralloc5의 allocator 선언 조회 안에서 대기했고, 서비스 매니저 없는 진단 대조는 mapper 선택을 모두 소진한 뒤 생성자에서 `SIGABRT`를 냈다. 실제 그래픽 버퍼 할당·import·lock에는 도달하지 않았다. ## 경로와 최초 실패 함수

## 필요한 Gralloc ABI와 VINTF

- **선택 순서**는 GSI `libui`의 Gralloc5 → HIDL 4.0 → HIDL 3.0 → HIDL 2.0이다. 2.1은 2.0 서비스의 선택적 확장이다. HIDL mapper는 각 버전의 `IMapper::getService()`로 찾되, 실제 mapper는 client 프로세스에서 동작하는 passthrough여야 한다. HIDL 4.0/3.0의 포맷 지원 질문은 mapper의 `isSupported`로 전달한다. 2.x에서는 `GrallocMapper` 기본 `INVALID_OPERATION`으로 인해 AHardwareBuffer가 실제 시험 할당으로 넘어갈 수 있으므로, mapper 로드만으로 통과한다고 볼 수 없다. [Gralloc4](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/android16-qpr2-release/libs/ui/Gralloc4.cpp) · [Gralloc3](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/android16-qpr2-release/libs/ui/Gralloc3.cpp) · [Gralloc2](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/android16-qpr2-release/libs/ui/Gralloc2.cpp) · [기본 런타임 반환값](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/android16-qpr2-release/libs/ui/include/ui/Gralloc.h)
- **Gralloc5의 최소 실제 구성**은 Guest private Binder의 AIDL `android.hardware.graphics.allocator.IAllocator/default` V2 이상과, 같은 allocator가 보고하는 suffix의 Android arm64 stable-C mapper다. `waitForAllocator`는 VINTF `isDeclared`, `waitForService`, `getInterfaceVersion ≥ 2`를 차례로 확인한다. 그 뒤 `getIMapperLibrarySuffix`로 `mapper.<suffix>.so`를 정하고, `AIMapper_loadIMapper`가 반환하는 `AIMapper`의 버전이 5 이상이어야 한다. 이 구성에서 capability 응답은 실제 allocator의 `IAllocator::isSupported`가 제공한다. `isSupported`가 성공적으로 true 또는 false를 반환하면 그 질의에서 버퍼 할당은 필요 없다. [Gralloc5 초기화](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/android16-qpr2-release/libs/ui/Gralloc5.cpp#49) · [isSupported 전달](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/android16-qpr2-release/libs/ui/Gralloc5.cpp#736) · [stable-C ABI](https://android.googlesource.com/platform/hardware/interfaces/+/refs/heads/main/graphics/mapper/stable-c/)
- **Android 16의 mapper 로드**는 `AServiceManager_openDeclaredPassthroughHal("mapper", suffix, ...)`를 사용한다. Guest device VINTF에는 AIDL allocator `IAllocator/default` 외에 native `mapper`의 `@5.0/<suffix>` 선언이 필요하다. libbinder에서 `isDeclared("mapper/<suffix>")`를 먼저 검사한다. 선언에 업데이트 가능 APEX가 있으면 그 namespace를 사용하고, 일반 vendor 배치는 `sphal`이 `mapper.<suffix>.so`를 읽고 매핑할 수 있어야 한다. 경로의 DAC/SELinux 접근과 의존 ELF 가시성도 필요하다. `mapper`는 앱 안으로 로드되는 라이브러리이고 AIDL allocator는 별도 Guest Binder 서비스다. Composer나 SurfaceFlinger의 기동은 이 호출 경로의 선행 조건에 포함되지 않는다. [Android 16 libbinder의 passthrough 로드](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/android16-qpr2-release/libs/binder/IServiceManager.cpp#556) · [실제 donor VINTF와 ELF](../out/guest-vulkan-b03/gralloc-apex.txt)

## 정상 Guest와 비교

11-19 기존 정상 실행은 `servicemanager.ready:true`, Guest Binder `234:5`의 handle 0, `aidl_lazy_test_1` 조회를 모두 실측했다. 같은 런의 Guest ServiceManager는 APEX 목록을 읽고 framework VINTF의 `ISystemSuspend/default` 선언 조회와 등록을 처리했다. 따라서 실제 private ServiceManager가 준비된 실행에서는 readiness 대기가 끝난 뒤 **allocator 선언 조회**로 넘어가는 것을 기대할 수 있다. 같은 정상 실행에서 device manifest `/vendor/etc/vintf/manifest.xml`은 `EACCES (-13)`였다. ServiceManager 준비와 framework VINTF 성공만으로 graphics device manifest, allocator 등록 또는 mapper 로드가 확보되지는 않는다. 이번에는 정상 private-Binder 세션에 ANGLE을 붙이지 않았으므로 그 조합의 반환값은 **UNKNOWN**이다. `servicemanager.installed=false`는 오류 분리용 대조이며 통과 판정은 없다. [기존 정상 readiness와 device VINTF 오류](../out/guest-vintf-20261119/run-1-detail.txt#L4) · [기존 framework 등록](../out/guest-vintf-20261119/run-1.txt#L14)

## 재현과 Host 확인

[B0.2 재현](guest-graphics-b02-swiftshader-pastel.md#재현)의 `guest-angle-b0.c` 빌드에 `-DSSAL_MAPPER_TRACE -funwind-tables -fno-omit-frame-pointer`를 추가한다. 기존 `angle` 모드에서 Pastel만 지정한 Guest 속성을 먼저 실행하고, Guest 서비스 매니저가 없는 진단 대조 fixture를 사용해 두 번째 실행을 기록한다. 두 로그의 `mapper-frame` 오프셋을 같은 Build ID의 ELF에서 확인한다. frame PC는 리턴 주소에서 1을 뺀 값이므로 AArch64 호출 명령은 4바이트 경계로 내림해 대조한다.

Host Binder, 그래픽 HAL, 물리 디스플레이, SELinux 정책을 변경하거나 연결하지 않았다. mock mapper나 allocator는 배치하지 않았다. 전후 SELinux enforcing 및 정책 해시, SurfaceFlinger PID, Host `/vendor`·`/odm` mount, SSAL mount 작업 디렉터리가 일치했다. [Host 전](../out/guest-vulkan-b03/host-before.txt) · [Host 후](../out/guest-vulkan-b03/host-after.txt)

실험용 프로세스와 마운트가 남아 있지 않음을 확인했다. 기기 staging과 WSL·작업공간 임시 파일을 정리했고, 보존한 증거 파일 7개의 SHA-256은 정리 전후에 일치했다.
